# Decisiones pendientes configurables

No se inventan políticas laborales. El software distingue configuración técnica de regla oficial.

- **Conteo de días:** configurable `CALENDAR_DAYS`, `WORKING_DAYS` o `SHIFTS`. Grupo A opera hoy con `CALENDAR_DAYS` (valor por defecto, no una decisión oficial confirmada por CFE/SUTERM).
- **Desempate y calificación mínima:** el concurso queda `rules_confirmed=0` hasta que un usuario autorizado capture y confirme ambos valores; no puede calcular ranking antes. Verificado en producción real en la Tarea 7 (CMP-01): sin `target_level_requirements` configurados para un nivel, el endpoint de evaluación de concurso rechaza abrir el concurso (`LONG_COVERAGE_REQUIREMENT_NOT_CONFIGURED`) en vez de asumir una regla. Este entorno todavía no tiene ningún requisito de nivel real cargado, así que el flujo de concurso completo (ranking, doble control de notas, inconformidades, adjudicación) sigue sin poder probarse con datos reales — no es una decisión pendiente de negocio, es un dato de configuración pendiente de captura.
- **Rechazo voluntario en rotación:** campo de política `rejectionConsumesTurn`; falta fijar valor oficial por grupo. Grupo A opera hoy con `rejectionConsumesTurn:true` (quien rechaza/deja vencer una oferta pierde su lugar y pasa al final de la fila) — es el valor que se usó para sembrar el piloto, **no** una decisión confirmada por CFE/SUTERM.
- **Cancelación de rotación ya iniciada:** la API exige que el responsable indique expresamente si consume turno; no adivina.
- **Ausencia justificada y posición:** pendiente de norma oficial; el motor actualmente salta indisponibles sin moverlos al final.
- **Firma formal:** roles técnicos existen, pero el rol oficial que firma cada acto debe definirse con CFE/SUTERM.
- **Cascada:** soportada y configurable con `cascadeEnabled`; por defecto está desactivada hasta confirmar que ese grupo debe encadenar todos los huecos. Grupo A opera hoy con `cascadeEnabled:false` (valor por defecto). Se probó temporalmente en producción durante la auditoría de la Tarea 7 (activarla, verificar que se encadena el nivel inmediato inferior con la transición correcta, y revertirla) — el mecanismo funciona, pero activarlo de forma permanente para un grupo real sigue siendo una decisión de negocio pendiente, no técnica.
- **Vigencia:** cada requisito puede exigir vigencia al inicio o durante toda la cobertura.
- **Tiempo de espera de oferta de rotación (`rotationOfferTimeoutMinutes`):** configurable por grupo (1–1440 minutos). Grupo A opera hoy con 1440 minutos (24 horas) — un valor operativo elegido para el piloto, más largo que el valor por defecto de 10 minutos, sin que exista todavía una política oficial de cuánto tiempo real debe tener un trabajador para responder una oferta de cobertura.
- **Roles operativos sin usuario real todavía:** `SUPERVISOR`, `HR`, `COMMITTEE` y `AUDITOR` existen en el modelo de autorización (`docs/SECURITY_MODEL.md`) pero no tienen ningún usuario provisionado en este entorno piloto (sólo `ADMIN` y `EMPLOYEE`). Definir quién ocupa cada rol en CFE/SUTERM es una decisión pendiente antes de producción real, no sólo una tarea técnica de alta de usuario.
